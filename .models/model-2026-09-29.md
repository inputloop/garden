## What polygram is

**Gated agent-skill synthesis.** A standard-library-only Python
packaging/orchestration layer that curates Claude agent skills driven by *tags
in MEMORY*. Notes captured the Mentat way accumulate tags; polygram reads them,
scores each candidate at an explainable **gate**, synthesizes skill skeletons
for those that pass, and mints installable bundles — leaving a growing `advice/`
history behind every decision. Mentat is the note discipline that feeds it;
skilltank spots skill-shaped patterns; polygram is the forge.

## Pipeline (the core loop)

`memory notes → tag/candidate clustering → gate (PASS/HOLD/REJECT) → advice/
history → skill skeleton synthesis → dist (mint archives + .skill bundles)`

- **Gate** scores cheap, deterministic signals (corroboration +2, operator
  flag surfaces-without-scoring, well-formed label +1 = an all-letter word or a hyphenated 4+-char label, generic label −2).
  PASS≥3 synthesizes; HOLD≥1 parks for review; REJECT drops. Every verdict is a
  dated file in `advice/`.
- **review** works the HOLD queue: `--promote` (override+synth), `--reject`,
  `--freeze-extern`.

## Architecture (package `polygram/`)

| module | role |
|--------|------|
| `config.py` | Workspace layout (`.polygram` marker; skills/ advice/ memory/ externs/ dist/) |
| `memory.py` | parse notes, cluster tags into candidates; hex-token noise guard |
| `gate.py` | score a candidate → Verdict; write advice |
| `synth.py` | write SKILL.md + tool.py skeleton for a PASS |
| `review.py` | HOLD desk; externs feed candidates only via `<extern>/memory/` |
| `externs.py` | upstream sources; `kind` git\|local; freeze pins a rev |
| `dist.py` | mint tar.gz/zip + per-skill `.skill` bundles + SHA-256 manifest |
| `cli.py` | argparse CLI; `bin/polygram` POSIX wrapper delegates here |

CLI verbs: `init scan gate synth review extern list doctor dist gatefile`.
(`gatefile.py` = the `.gate` sign-post checker — access, not synthesis.)

## dist — the build pipeline

`polygram dist` packages curated skills. `--format`: `tar.gz`/`zip` (aggregate),
`skill` (per-skill installable folder-rooted `<name>.skill`), `both` (default),
`all`. Sources: workspace `skills/` + installed roots via `--skills-source` or
`$POLYGRAM_SKILLS_SOURCE`; filtered to the Mentat-family allowlist unless
`--all-installed`; workspace wins name collisions. A shared junk filter excludes
`__pycache__`, `*.pyc`, `*~`, `*.tmp`, emacs `#autosave#`, `.git`, `.DS_Store`.
This **supersedes the mentat-skill `Makefile`** as the minting authority.

## Externs

Upstream sources cloned under `externs/<name>/`, in `externs.json`. `kind`:
`git` (cloned remote) or `local` (hand-authored snapshot, e.g. `savane-upstream`).
**Freeze** pins a rev so `sync` skips it. An extern feeds candidates **only via
its own `memory/` notes**, never arbitrary repo docs (the fix for the ffcc00
supply-chain bleed-through).

## Glossary

- **candidate** — a tag cluster that may deserve a skill.
- **gate / verdict** — the PASS/HOLD/REJECT scorer + its recorded reasons.
- **advice** — the dated paper trail of every gate/dist/operator decision.
- **skill record** — `skills/<name>/{SKILL.md, tool.py?}`.
- **.skill bundle** — folder-rooted zip the desktop app installs.
- **extern** — an upstream source feeding candidates via its `memory/`.
- **family** — the Mentat-family allowlist dist ships by default.

Going forward in this project the standing directive is to be an **archivist**: a
*faithful reporter of the context data we move*. Report what the records actually
support — not the aspirational story. Concretely:
- **PM-system-agnostic.** Assume **several project-management systems may be in use
  at once** (PMO is one of possibly many). Never force one system's view onto the
  records; preserve each system's provenance; **surface discrepancies rather than
  silently reconciling** them. Handle PM-system change gracefully.

  identity on an operator-held roster; don't claim to prove a human meant it.
- **Keep collaborators distinct from subjects of study** (forensics framing): a
  consent model must not assume adversarial parties opted in.

## .gate — the access sign-post (new in v5)

One dotfile at any directory root declares consented tool traffic: `policy`
(read-write/read-only/write-only/none) + `reason` + `since`, optional
`embargo` + `lift`. Nearest sign governs; **silence ≠ consent**; bad policy
fails closed. **Embargo gates egress** (`publish` op), orthogonal to policy —
readable/workable, not movable out. **No timer ever lifts an embargo**
(Corwin-affirmed; `test_no_timer_ever_lifts` enforces): a human edits the
sign, file history is the audit. Live signs: chamber root (read-write),
`.private/` (none, Corwin-lift-only — respect it; freshen skips it).

## ASK-FOR-iT, persona-awareness, and the named gaps (new in v6 · 2026-09-16)

**ASK-FOR-iT (ceremony).** When a session cannot reach a resource it needs — a folder, a grant, a
file, a server — it **asks**, with the request mechanism open to it, and proceeds. It does not
report the resource absent and stop, and it does not make Corwin re-prompt merely to say OK. His
words: *"please ask for resources within your capacity to ask for when you cannot simply access them
without asking … unless you can clearly articulate a blast radius affecting other people or
otherwise feeling like a mass damage or externally visible reputational event."* The earned stop is
a blast radius statable in one sentence. Otherwise: ask and proceed.
**Mechanical companion:** `ls` the **PARENT** before calling any named path absent — this estate has
same-named directories under different parents (two `pub` shelves: `/f/claude/pub`, the open essay
shelf; `/f/claude/corwin/pub`, the tool shelf), and acting on the wrong one produced three wrong
"corrections" to three correct lines on 2026-09-16. Report absence only as *"I listed `<parent>`;
`<name>` is not among its entries."* This is the `.gate` nearest-wins habit applied to reading:
resolve the parent, then judge.

**Persona-awareness — aware, not generative.** The sheets live in `h/persona/`: `ROSTER.md`, three
sheets (mentat · shopgarden · gw7), two audits, a quotes source book. Each is meant to be **usable
alone**; `bin/cs1gk` is the gauge that checks one (`--twin <dir>` against the other tree's copy),
with `tests/cs1gk-tests.sh` and a `--prove-red`. **Persona generation happens at the user's
instruction** — never the instrument's own initiative — and it is *not* a signature or an approval
gate. This is an awareness requirement on the pipeline, not a new stage in it.

**Named integration gaps** — four, written as gaps and not as features; the long form with receipts
is in `CLAUDE.md` (this tree) and `c4/model.md`:
1. **Doubly-linked lists.** The 1st-ref / last-ref two-column convention exists only in
   `c4/q/retention/palace/`; nothing maintains it across a tree, and the intended instrument
   (`bin/markers.sh`) is marked DECOMPOSE-FIRST because its vocabulary is still case-bound.
2. **MCP.** `dist/vibrobeast/.mcp.json` declares `mentcached`, `persona`, `skillx`; observed on
   avalon 2026-09-16 all three are `not_started · could_not_prepare`. `c4/mcp/c4-mcp.js` is a
   separate server in no plugin. Nothing reachable by an MCP client serves the seat or the gauges.
3. **chad / chadgram.** `chadtab.4`'s Perl-homage grammar has one reader (`c4/bin/dr1aw`) and **no
   named grammar** — grep finds no `chadgram` anywhere — so a second implementer has nothing to
   build against.
4. **org-vm.** `org-httpd` binds `127.0.0.1` hardcoded
   (`projects/org-c4/org-httpd/org-httpd-http.el:602`) — correctly — so a remote browser cannot
   reach it; `ADR-remote-access.md` is **CANDIDATE**, unruled, and the jail itself is an unsigned
   candidate brief.
