*Gated agent-skill synthesis.* A small, standard-library-only packaging and
orchestration layer that curates Claude agent skills driven by /tags in
MEMORY/. Notes captured the Mentat way accumulate tags; polygram reads those
tags, evaluates each candidate at a *gate*, synthesizes skill skeletons only
for the ones that pass, and mints installable bundles — leaving a growing disk
history of "advice" behind every decision.

#+begin_quote
/It is by will alone I set my mind in motion./
#+end_quote

* What you get
- *The vibrobeast plugin* (=dist/vibrobeast.plugin=, minted by =make dist=): the
  curated skill garden in =skills/=, one installable =.skill= per skill, and the
  MCP servers that need nothing but Python 3.10+: =mentcached= (a memory seat
  with chained, dated notes), =persona= (character sheets read from the shelves
  you name) and =skillx= (skill exchange between gardens), always present; and
  =llamabridge=, =tavernface= and =c4face=, off until you ask Claude to turn them
  on.  The plugin's own README counts them and lists the switches, minted from
  the code (=polygram/plugin.py=, =SERVERS=), so that count cannot go stale.
- *Sized editions* for a new place: the floor of eight (=polygram/editions.py=, =FLOOR=) plus a share picked by
  use (=make edition SIZE=grain=); the rest stay findable as soft skills.
- *The forge itself*: the gate, the advice trail, synthesis, externs, and a
  release pipeline that signs, checks for secrets at every way out, and refuses
  to mint what it could not check.

* Quick start
To use it, take a signed release from the public shelf,
https://code.bru.st/corwin/vibrobeast (=releases/=): install =vibrobeast.plugin=
(or any single =.skill=) in the desktop app, and check it against its =.asc=.

To build it, from a checkout of this source tree:
#+begin_src sh
sh bin/polygram doctor      # the runtime and the workspace
UNSIGNED=1 make dist        # mint dist/ (no signing key needed)
make check                  # the python test suite
#+end_src
Then install =dist/vibrobeast.plugin=. =INSTALL= has the rest, including how to
verify a signed release.

* With or without C4
C4 is the author's wider registry, and this project is one of the gardens it can
read. It is not needed here. Every skill says what it does on its own, a shipped
copy of a shared tool runs alone, and the whole garden check passes without a C4
tree (=sh bin/gd1ck --no-c4=). When a C4 tree is in reach (=C4_ROOT=, else
=/f/claude/c4=, else =~/mnt/c4=), a few things read more: =garden-usage= reads its
name registers, =make garden= gauges installed copies against the curated ones,
and =make dist= adds a publication read. Where a skill names C4 it is credit for
where an idea came from, not a requirement.

* Why
- *Packaging / orchestration* over a collection of reusable, stdlib-only tools.
- *Memory-driven*: the labels, phrases and keywords that matter to the project
  (Mentat, shell-tooling, …) decide what becomes a skill.
- *Gated*: nothing auto-promotes. Each candidate is scored on cheap, explainable
  signals and the verdict is written to =advice/= as a dated file.
- *POSIX-delegating*: a thin =sh= entry point so the same toolchain runs across
  local environments.
- *Tested twice*: a check that matters is written again, from a prose spec, in a
  second language, and every suite can show itself going red (=--prove-red=).

* The pipeline
=memory notes → candidates → gate (PASS/HOLD/REJECT) → advice → skeleton synthesis → dist=

A note earns a candidate through *tags*: org-style heading tags
(=# Keep replies tight :SKILL:=) or inline hashtags (=delegates to shell #shell-tooling=).
Control tags (=:SKILL:=, =#skill-candidate=, =#synth=) /promote a note's other
tags/ rather than becoming skills themselves.

** The gate
| Signal                         | Effect |
|--------------------------------+--------|
| corroborated by >=2 notes      | +2     |
| explicitly flagged by operator | surfaces only (no score) |
| well-formed label (a word, or a hyphenated 4+-char label) | +1 |
| overly generic label (misc, …) | -2     |

=PASS= (>=3) synthesizes a skill; =HOLD= (>=1) records advice but waits;
=REJECT= is logged and dropped. Every verdict lands in =advice/=.

* Usage
Every script is run through =sh= below, on purpose: a clone made by git on
Windows (and some archive tools) leaves no execute bit, and =sh bin/polygram=
works either way. First steps on a fresh clone are in =INSTALL=.
#+begin_src sh
sh bin/polygram init        # create the workspace here
sh bin/polygram doctor      # check python + POSIX runtime
sh bin/polygram scan        # show skill candidates from memory
sh bin/polygram gate        # evaluate candidates, write advice (no synth)
sh bin/polygram synth       # gate + synthesize everything that PASSes
sh bin/polygram review      # work the HOLD queue (--promote/--reject)
sh bin/polygram list        # list skills and recent advice
sh bin/polygram dist        # mint tar.gz + zip + .skill bundles
#+end_src

=PYTHON=python3.12 sh bin/polygram …= overrides the interpreter; =-C DIR= runs as
if started elsewhere.

* Dist — minting your curation
=synth= leaves curated skills under =skills/=; =dist= packages them. It gathers
the workspace plus any installed "Mentat & family" skills you point it at,
writes a =MANIFEST= with a SHA-256 per file, and mints =.tar.gz=, =.zip=, and
per-skill installable =.skill= bundles.

#+begin_src sh
sh bin/polygram dist --format all                       # tar.gz + zip + .skill
export POLYGRAM_SKILLS_SOURCE=~/.claude/skills         # set once…
sh bin/polygram dist --format skill                     # …then no flag needed
#+end_src

A =.skill= is a folder-rooted zip (=<name>/SKILL.md …=) the desktop app installs
directly. Editor/build cruft (=__pycache__=, =*.pyc=, =*~=, =*.tmp=, emacs
=#autosave#=, =.git=, =.DS_Store=) is excluded from every archive and bundle. On
a name collision the workspace copy wins. This supersedes a hand-rolled
packaging Makefile for plain packaging — the =Makefile= that ships with this
repo is a thin convenience wrapper around it: the secrets scan, signing, the
version stamp and the plugin in one word (=make dist=), and, when a C4 tree is
in reach, gauging installed copies against the curated ones (=make garden=).

* Makefile targets
=make help= lists them; the two worth knowing:
#+begin_src sh
make check                  # python3 -m unittest discover -s tests -v
make dist                   # mint skills/ (the garden): every skill, signed,
                             # plus the plugin; secrets checked first
make garden                 # gauge: is every skill's worn copy the curated
                             # copy, across this repo AND the wider C4 tree?
                             # exit 1 = something needs a look
make kit                    # the whole-garden test + benchmark kit (bin/gd1ck):
                             # every suite here and in C4_ROOT, each --prove-red
                             # twin, skill lint + size, plugin bytes, garden
                             # gauge; results recorded to metrics/
make kit-quick              # the same without the two slow legs
make metrics                # the metrics store, latest row per item
make skills                 # python3 -m polygram synth
make info | make clean      # build/remove the Texinfo manual
#+end_src

=garden= and the =CANON=/=SG1CK= paths =dist= now also uses need a =C4_ROOT= —
the tree root for the wider C4 registry this repo's skills are gauged and
minted against. =C4_ROOT= auto-detects (2026-09-12): it prefers the real host
path when present and falls back to a mounted sandbox copy otherwise, so a
fresh sandboxed session's first =make garden= no longer dies on a hard-coded
host-only default. Override it, when the default guess is wrong for your
tree, either way:
#+begin_src sh
make C4_ROOT=$HOME/mnt/c4 garden      # command-line override
C4_ROOT=/some/other/tree make garden  # environment-variable override (new)
#+end_src
=tests/makefile-c4root-tests.sh= proves all four cases (auto-detected host
path, auto-detected sandbox fallback, and both override forms) against the
live =Makefile=, not a reimplementation of its logic; run it with
=sh tests/makefile-c4root-tests.sh= (add =--prove-red= to check the harness
itself would go red on a planted bad expectation).

* Externs and freeze
Externs are upstream skill sources you clone in. An extern feeds candidates
*only through its own =memory/= notes* — not arbitrary repo docs, which would
let upstream noise surface as skills. *Freezing* pins an extern at a revision so
=sync= skips it. A =local= extern is a hand-authored snapshot with no remote.

#+begin_src sh
sh bin/polygram extern add up https://example.com/up.git --ref main
sh bin/polygram extern add snap "" --kind local      # hand-authored snapshot
sh bin/polygram extern freeze up --rev 9f1c2ab
sh bin/polygram extern list
#+end_src

* Tests
#+begin_src sh
make check                                  # python3 -m unittest discover -s tests -v
for t in tests/*-tests.sh; do sh "$t"; done # the shell suites (most take --prove-red)
sh bin/gd1ck --no-c4                        # all of it, one verdict per item
#+end_src
A suite whose input or interpreter is absent here (no =dist/= yet, no C4 tree,
no ruby >= 3) prints =SKIP:= and exits 77; =bin/gd1ck= shows that as SKIPPED
and counts it as not checked -- never as a pass, never as a failure.
