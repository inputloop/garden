# MODEL — the Mentat audit: what the name meant, what the skill kept, what fell in the gap

*Opus 5, 2026-09-13, at Corwin's ask ("I didn't see the Mentat skill fire. Is that fine?").
Two piles, per CLAUDE.md: what I OBSERVED, each with the command or file that produced it, kept apart
from what I JUDGE, each tagged and each carrying the one check that would dissolve it.
Marked: for analysis — no ship dates or licensing or publication dates specifically defined.*

---

## 0 · The short answer

No, it is not fine, and the reason is better than I expected. The Mentat skill did not fire on the
compaction because **compaction is not in its trigger**, and the skill's own safety rule for exactly
that operation is written *inside the body*, where only a session that already triggered it can read.
The highest-risk memory operation in the house is the one whose safeguard is unreachable from its own
front door. That is a literal gap, it is mechanical, and it bit: nine of fifty-four lifted hooks went
missing from the archive on 09-12 and nothing caught it until this audit.

The larger finding is not about memory at all. **The name "Mentat" in Corwin's own tree is an author's
byline, not a memory discipline** — and the skill that carries the name kept only the part Mentat never
did in the tree. That is the real accounting of drift, and it is mostly not drift.

## 1 · OBSERVED (facts, each with its receipt)

**O1. The 09-12 compaction preserved every entry.** Store A's index carries 145 unique link targets
before and after; the check that produced this, run 2026-09-12, was
`diff <(grep -o '](...)' A/MEMORY.md | sort -u) <(same over the new index)` → identical, and re-run
2026-09-13 over the file on disk: 145 targets, 122 lines, 20045 bytes
(`wc -lc .auto-memory/MEMORY.md`).

**O2. Nine of fifty-four lifted hooks did not reach the archive.** Re-derived the lifted set and diffed
it against `memory-index-archive-2026-09.md`: 54 lifted, 9 absent. Cause: the archive block was composed
by hand in an Edit instead of pasted from the generated `outputs/lifted.changed.md`. Repaired this
session; re-run of the same diff now reports `lifted: 54  still missing: 0`.

**O3. No knowledge was lost by O2.** All nine notes are present as files on store A's disk
(`for n in <the nine>; do [ -f .auto-memory/$n.md ]; done` → all present). The full text was always one
read away.

**O4. Sixteen index lines in store A point at notes store A does not hold.** Both readers agree:
`comm -23 <A index targets> <A disk>` returns 16, and the file tool returns "File does not exist" for
`signing-silence-rule.md` under A. All sixteen exist on the seat
(`[ -f AS4CE0001/memory/$n.md ]` → 16/16 present). This predates 09-12: the link set was byte-identical
before and after that compaction (O1), so the compaction neither created nor healed it.

**O5. The sixteen of O4 and the nine of O2 do not overlap.** Set intersection is empty (run this
session). Every hook whose shortened form was the only copy of that note *in store A* reached the
archive. That is luck, not care — nothing in the procedure ordered it.

**O6. `ms1dg` assumed a single index page and manufactured keeper work.** With `IDX="$SEAT/MEMORY.md"`
alone: G3 reported 111 notes "STRANDED-IN-SEAT" with the card "add one index line each", and G8 reported
"51 line(s) in A's index missing from the seat index" with the card "append those lines … on the host".
Counting the seat's other index pages, both go to zero: `A-only vs MEMORY+page2 = 0`, stranded 111 → 2
(the two are `MAIN-MEMORY-DESYNC-WORKPLAN_000.md` and `MEMORY.MOVED.md`, genuinely unindexed). The seat
has carried a second index page since 2026-09-11 (`memory-index-2026-09-11.md`, 109 notes, its own
header says so).

**O7. The Mentat skill's description never names compaction.** Its trigger words are capture ("make a
note", "remember that", "keep track of") and review ("review, tidy, audit, or prune existing memory",
"clean up memory", "what do you know about me"). The 09-12 rewrite was triggered by a harness
`PostToolUse` reminder reading "Compact it to under 140 lines now" — a hook, not a person asking to tidy.

**O8. The skill's bulk-rewrite safeguard is inside the body.** `mentat-skill/SKILL.md`, under
"Truncation is the mind-killer": *"For a bulk memory rewrite — many notes rewritten at once, where the
desync risk climbs — don't reinvent the safe write: use the `sandboxer` skill's atomic write-and-verify
path."* Nothing in the description surfaces it.

**O9. The index's size and shape rules live in a vendor skill.** `consolidate-memory/SKILL.md` Phase 3:
*"Update `MEMORY.md` so it stays under 200 lines and ~25KB. One line per entry, under ~150 chars."*
The house skill hands tidying to it: *"hand off to the `consolidate-memory` skill, which exists for
exactly that reflective pass."* That vendor skill's text contains no mention of a seat, a second store,
a continuation index page, a fence, or `ms1dg` (grepped its full text).

**O10. "Mentat" is an authorship byline in Corwin's dungeon repo, predating the memory skill.** Exact
forms, from file headers: `;; Author: Mentat (for Corwin)` on five `src/dm-cell*.el` modules;
`#+AUTHOR: Mentat (for Corwin)` on four `MENTAT-*.org` documents; `#+AUTHOR: Mentat (for Corwin & Erik)`
on three more. Copyright vests in the human on every one: `;; Copyright (C) 2026 Corwin Brust` sits
above the Author line. Git authorship is Corwin's; the Mentat byline exists only inside the file text.
Dates: 2026-06-23 through 2026-07-01.

**O11. The labour split is spelled out in the tree.** `Docs/combat.org:2` —
`#+AUTHOR: Corwin Brust (rules), transcribed & formalized by Mentat`. `Docs/saving-throw.org:2` —
`#+AUTHOR: Corwin Brust (rules), formalized by Mentat`. The human owns the rules; the persona
transcribes and formalizes.

**O12. Dungeon-Mentat's voice already practices the eight mutations, three months before they were
written.** Receipts over claims: *"Net: ~+29 tests now actually run (≈118 total)"*
(`MENTAT-TEST-AUDIT.org:41-42`). Refusal to assert what was not run: *"I cannot run Emacs in this
sandbox, so I static-checked instead … Please run `make test` and tell me the count."*
(`MENTAT-TEST-P2.org:16-19`). Plain admission of its own error: *"`ert-with-message-capture` captures
NOTHING under `emacs --batch` … so it returns "" and the assertions failed."* (`MENTAT-TEST-P2.org:46-48`).
The eight were adopted 2026-09-04/05 after a LENS read.

**O13. Nothing in the dungeon Mentat corpus concerns memory.** A grep of all eight named files for
`memory|journal|remember|continuit|persistent` returns only the game's own unbuilt journal feature,
"in-memory" in the RAM sense, and *Corwin's* recall of house rules. Reported as an explicit negative
result by the reader, not an omission.

## 2 · JUDGED (each tagged; each with the check that would dissolve it)

**J1 — the trigger gap. [SKILL]** The operation with the highest desync risk (bulk index rewrite) is
the one the skill's description cannot see, and its safeguard (O8) is only legible after triggering.
A harness hook can therefore drive a memory rewrite with no discipline attached, which is what happened.
*Falsifier:* add "compact", "the index", "MEMORY.md" to the description; if a later session still
rewrites the index without the skill loading, the gap is elsewhere and this fix is wrong.

**J2 — the index promises what the store does not hold. [SKILL]** Store A's loaded index names sixteen
notes store A lacks (O4); one of them, `signing-silence-rule`, is a STANDING rule. A session reads the
hook, reaches for the note, and gets nothing — with no line telling it to look at the seat.
*Falsifier:* mark each such line with its home store and re-run the dangling check from a session that
only has A; if it still cannot reach the text, marking was not the fix.

**J3 — the gauge was moving his gauge. [MINE]** `ms1dg` put roughly 162 lines of hand-work on the
keeper's desk every session (111 + 51, O6), none of it owed. His own note says the prompt-pressure count
measures deferral and that *I* move it. A tool of mine inventing keeper rows is the mechanical form of
that same failure. Fixed this session; G8 now reads `no line the seat index set lacks`, stranded is 2.
*Falsifier:* run `ms1dg` on a single-index store and confirm the old behaviour is unchanged there — if
the multi-index path changed a single-index verdict, the fix over-reached. (Run: tests 37/37, including
four new fixtures for exactly that.)

**J4 — the handoff sends the embassy to a stranger. [MINE]** The house's most house-specific operation
is delegated to a vendor skill that knows nothing about the seat, the fence, the second page, or the
gauge (O9). Its "one line per entry" is also the only written rule about index shape anywhere, which
means the house has been taking its index law from a skill that has never seen the house.
*Falsifier:* write the house convention (done, this session) and check whether `consolidate-memory` is
ever the right call again; if it is, the handoff was fine and only needed a house preface.

**J5 — the packed line was mine, unblessed. [MINE]** I invented multi-notes-per-line on 09-12 to fit a
200-line budget. It satisfies the budget and breaks "one line per entry" as the vendor skill words it.
Nothing in his writing blesses or forbids it. It parses correctly for every tool that reads link targets
(`ms1dg` uses `grep -o '](…)'`, verified), so it is safe; it is still a shape he did not choose.
*Falsifier:* this is a fork, not a concern — see §5.

**J6 — most of this is not drift. [MINE]** The eight mutations were adopted in September after a LENS
read; dungeon-Mentat was already practising them in June (O12). The skill did not drift away from a
standard — the standard was being *practised before it was written*, and the writing-down in September
captured one room of the house. Two rooms were never written at all: the byline convention (O10) and the
labour split (O11), both of which have been running in his tree since June with no skill that knows they
exist. *Falsifier:* find one instruction, blessed or written by Corwin before 2026-09-04, that tells
Mentat to keep memory. I looked in the dungeon corpus and found the opposite (O13); if such an
instruction exists elsewhere, this judgement is wrong.

## 3 · The accounting he asked for

**Breakage** (mechanical, was wrong, now fixed or fixable): the single-index assumption in `ms1dg`
(O6/J3 — fixed, 37/37); the nine dropped archive lines (O2 — repaired); sixteen index lines pointing out
of their own store (O4/J2 — needs a marking pass, listed in §5).

**Drift** (moved away from something established): thin, and only one item — the handoff of index law to
a vendor skill (J4). The packed line (J5) is not drift but an unblessed invention of mine, which is a
different thing and is offered as a fork rather than defended.

**Never well enough defined to write down until now** (the bulk of it): that compaction is a Mentat act
at all; what an index page may look like and when a second page is born; which store a note's index line
belongs to; that Mentat has a byline, and what it is; that copyright vests in the human; that the human
owns the rules and the persona formalizes them. Every one of these has been *practised* — some since
June — and none was written. That is the honest weight of the answer: this is mostly a house that knew
how it worked and had not said so.

## 5 · What is his, and cannot be mine

**Fork A — the packed index line.** Keep it (fits the budget, parses everywhere, costs one-note-per-line
legibility), or revert to strict one-line-per-entry and accept a third index page instead. I lean keep,
and I would rather be told.

**Fork B — the sixteen A-lines pointing at seat-only notes.** Three shapes: mark each line with its home
store; copy those sixteen notes into A so the store is whole; or declare the loaded index a *catalogue*
of the union and write that down, which makes O4 correct behaviour rather than a defect. I lean the
third — it is what the store is actually doing — but it is a statement about how his memory works and
that is his to make.

**Fork C — Mentat's scope.** The tree's Mentat writes code, audits tests, formalizes rules and signs
its work. The skill's Mentat keeps notes. Either the skill grows to cover the byline and the formalizer
role (the v2 draft takes one step toward this: it claims the byline, not the code), or the byline gets
its own skill and Mentat-the-memory stays narrow. This is the ambassador question and I have deliberately
stopped short of deciding it.

**Fork D — installation.** I do not install or enable his skills. The v2 draft sits in `h/` until he
reads it.
