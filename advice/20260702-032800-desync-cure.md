# advice: mount desync — cause narrowed, in-sandbox cure found, tool shipped

- when: 2026-07-02
- context: "one time, harder-edged" probe authorized by Corwin before other work

## Disclosure honored (foundry record)

Corwin disclosed: exactly once, he ended the sandbox's processes in Task
Manager host-side; the desync cleared. Under his standing "don't dig" policy
he did not inspect further. This session's findings substantiate his data
point into information: the mounts are FUSE — a userspace bridge to the
Windows folders — and the staleness lives in the bridge's per-node cache,
which a host-side process restart naturally resets.

## Probe (controlled, two rounds)

Repro: file-tool fresh write → bash read (poisons node cache) → file-tool
in-place edit → bash serves old bytes at old length, **stat stale too**.

Cures tried guest-side: posix_fadvise DONTNEED — failed; O_DIRECT read —
failed/unsupported; touch — failed. (Consistent: staleness is in the FUSE
bridge, not the guest page cache.)

**Cure that works: the rename dance.** `mv f f.tmp && mv f.tmp f` forces the
bridge to re-resolve the node; fresh bytes and correct stat follow. Verified
twice on the probe file, then on the real casualties (cli.py, gatefile.py,
test_gatefile.py, GRAMMARY.md). Suite then ran **64 green directly on the
mount** — first time; overlays no longer required, only the dance after
in-place edits.

## Shipped

- `bin/freshen` (POSIX sh): `freshen FILE...` / `freshen -r DIR`. Skips
  `.private` trees (policy none). On failure (host lock) it names the
  fallback: Corwin's Task-Manager reset. Self-tested (freshened itself).
- `.private/.gate` posted: policy none, lift Corwin-only — the sign-post's
  first `none` tenant, and the posting write is recorded in the sign itself
  as the last tool write there. Live check: read and write both DENIED under
  `.private`, root remains read-write. Nearest-wins demonstrated in the wild.

## Standing guidance (supersedes overlay-first)

After any file-tool in-place Edit that bash must consume: `bin/freshen` the
touched files. Fresh writes never need it. If freshen FAILS, fall back to
the host-side process reset (Corwin's move), or the /tmp overlay as last
resort. git on the mount remains forbidden (#25) — freshen fixes reads, not
the write-side desync behind that rule.
