## 2026-09-13 — E15: a detector's false positives are a map of its domain's grammar

Narrowing `hb1ck --defer` (does a deferral carry its blocker?) turned out to be a lesson about text,
not about handbacks. The check was written against fixtures and looked fine. Run against real files in
the tree, it produced five distinct classes of false positive, and every class named a **register** —
a place in a document where words do not mean what they say in prose:

1. **Mention vs use.** A file documenting the tokens faulted on its own documentation: the literal
   `[BUDGET: N]` in a usage line has no figure. A backticked span is a mention.
2. **Data vs prose.** `| 10 | be the one who is owed |` — a row of a game book's random table.
3. **Structure vs promise.** `## 5 · ENHANCE — out of scope for this round` — a heading labels; it
   does not undertake.
4. **Vocabulary vs speech.** `DEFERRED` in caps is a verdict being applied. CAPS is the label channel
   in this house, which is already written down as `c4-load-bearing-character`, and the fix fell
   straight out of a convention that had been sitting there all along.
5. **Fenced code.** Not prose, and never was.

The fix is one awk pass building a **prose view** that preserves line numbers and blanks everything in
another register. That is a reusable shape, and it is the spoiler: *any* detector that greps a markdown
tree for intent needs the same preprocessing, and the list above is close to complete for this house's
document grammar. Reach for the prose view before writing the next one.

Two side notes worth keeping. The check also had a live shell bug — `n=$(grep -c . "$t" || echo 0)`,
where grep exits 1 on no match so the fallback appends to grep's own `0` and `[ "$n" -eq 0 ]` gets
`0\n0`, "Illegal number". That is exactly the `posix-gotchas` footgun, **already fixed once in the
neighbouring function in the same file and missed here.** A footgun fixed locally is not a footgun
retired. And `--claims` turned out to recognise only `C`-prefixed ledger rows, so it silently refused
a whole ledger that used `D` — found by running the check on the ledger of the session writing the
check.

Related: the round's other spoiler is that `gb1md --render` and `--thread` deliberately print counts
and no verdict, because four graded books cannot validate a threshold, and a threshold
picked-not-validated is the fault the gauge exists to catch (`countable-gauge`).
