# MODEL — a written step is not a proven step (DRAFT, unsigned)

*Charter class: method travels, cases don't. Minted 2026-07-13 from three
self-inflicted failures in one session. ENHANCE-candidate for
MODEL-honest-instrument rather than a permanent sibling — skilltank's call.
Parked unsigned; no signing debt incurred while the keeper is at the bench.*

## The claim

**An instrument's account of its own work is not evidence.** Not its confidence,
not its fluency, not its memory of having checked. This is the same law the shop
already runs (*the writer never grades its own homework*) turned on the writer of
the doctrine itself — and it has to be, because the failure mode is invisible
from the inside.

## The three specimens (one session, 2026-07-13)

1. **The card that could not be pasted.** A run-card named
   `scripts/skill-sign.sh`; the tool lives at
   `skills/skill-sign/scripts/skill-sign.sh`. The card was written to be
   paste-ready and was never pasted anywhere. The keeper's shell found the truth
   in one line. *A card is a measurement scheduled in advance — and a
   measurement nobody ran is a plan, not a measurement.*
2. **The count that was recited, not counted.** A release plan asserted "14
   skills, sweep must read 14/14." The tree holds **18**. Nobody counted; the
   number came from a prior, and priors sound exactly like facts.
3. **The phantom copy.** A `cp` from bash of a file the file-tool had edited
   produced a byte-identical *phantom* — the tool's own doctrine (F1) predicted
   it, and the instrument walked into it anyway, forty minutes after writing the
   rule down. *Knowing the law is not obeying it; the check is what obeys.*
4. **The false BAD, stated as fact — twice.** The instrument ran
   `skill-sign verify` from the sandbox over three trees whose `SKILL.md` it had
   edited that session, and reported "3 trees unsigned" to the keeper. The keeper
   had signed them. The verifier hashes **through bash**, and bash was serving a
   *phantom* of every file the file tool had touched — so the ceremony judged
   bytes that do not exist. The host said `signature valid` for all three.

   **The rule this earns, and it is stronger than "cross-read":** a tree whose
   files were changed from the sandbox this session **cannot be verified from the
   sandbox at all.** The correct output is not BAD and not OK — it is *"I cannot
   check this; the host is the only valid reader."* An instrument that cannot see
   must say so, not guess. Reporting a false BAD is worse than reporting nothing:
   it spends the keeper's trust and invites a destructive "repair."

## What the specimens have in common

Each was **fluent, plausible, and unverified** — and each was caught in seconds
by *running the thing*. None would have been caught by more thinking. That
asymmetry is the whole model: for a machine, thinking is cheap and lying is free,
so the only currency is the observable.

## The operating rules

- **Run it before you write it down.** Any command, path, count, or flag that
  will appear in a card, a README, or a release note gets executed first. If it
  cannot be executed here, say so *in the artifact* — "not rehearsed; needs the
  key" is honest; silence is a claim.
- **Count, don't recall.** Any number in a deliverable is a measurement with a
  command behind it, or it is decoration.
- **The freshest doctrine is the most likely to be violated.** A rule written
  today has no reflex behind it yet. Check yourself hardest where you have just
  become an expert.
- **Corollary, and it is the keeper's:** *a push is a fact; a release is a
  claim.* Publishing a tree says "here it is." Cutting a release says "this is
  fit, under my key, and strangers may pin it." Test yourself between the two
  acts — the gap between them is where the instrument's self-report gets
  replaced by evidence.

## Why this is not self-flagellation

Every one of these was cheap: minutes, no data lost, all three caught by the
keeper or by a check. That is the system *working* — and it is the argument for
the whole apparatus. The instrument does not need to be trustworthy; it needs to
be **checkable**, in a shop where checking is cheap and someone always argues.

*Mistakes are the resume of every tool-builder. This page is the resume kept
honestly.*
