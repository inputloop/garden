## The durable doctrine (compressed)

- - **SEAMS law.** Two independent sources must agree, with a named tiebreaker;
  a single source is data, not proof. Unifies the reader, consent, and
  empty-is-not-proof disciplines below.
- - **Reader-trust rules (sandboxer).** New files read fresh everywhere; a file
  *edited through the file tool* then reads stale to bash — so after an edit,
  bash is not a valid verifier for it. Verification is itself a read (a sig
  check over stale bytes yields a false BAD — never declare broken off one
  reader). Absence is a read too (one tool's "not found" + another's hit = a
  stale search). A timeout does not undo a write — verify before any retry.
- - **Signing idiom (standing rule).** Signature form follows artifact class:
  machine-parsed or executable artifacts (SKILL.md frontmatter, scripts,
  bundles) take a **detached** sig or a whole-tree manifest; prose meant for
  human reading takes **clearsign**. Clearsign's header + dash-escaping break
  YAML fences and shebangs — house-verified.
- - **Close-pins.** At any declared close: keeper-binding gates live as SIGNED
  data on the keeper's surface, not as conversation; an answer that may have
  hit a dead/errored turn is resent or transcript-audited, never retyped;
  count work-order prompts against reframe files; a broken-tail close names
  the fact in its filename before re-sign.
- - **Relay fidelity.** Anything production-shaped is tagged observed / proposed
  / hypothetical, both directions — an imprecise relay is itself a hazard.
- - **PACE.** A pace nudge must cite an observable or the keeper's own
  declaration; generic priors are context, never basis.
- - **Empty is not proof.** Prove the negative; absence of a finding is a
  question to substantiate, not a conclusion.

## Wire-standing (ALPHA, one breath)

Peers are keeper-backed and reciprocal; delegates (local models via a bridge)
are keeperless, verified-every-output, owned upward. Capability is the
symptom; **keeper-backing and the direction of accountability** are the
boundary. Two-port lens: delegation is the down-port (MCP-shaped), peer
coordination the across-port (A2A/ANP-shaped); cross-model reach is
Peer-over-Delegate, never a delegate promoted on capability. Model verified
signed 2/2 this round.

## Cross-garden etiquette (candor-gate)

An imported skill clears five checks before acting in a shop that didn't
author it: provenance vs the author's *pinned* key ("valid" = nothing changed
since they signed, not "someone I know signed something"); opt-in, not silent
always-on; consent before persisting third-party/family facts; consent for any
egress; no dangling routes. Warm at the gate, exact about the papers. Prefer
fold-with-credit over deriving a rival (rail-laundering guard).

## Tonight's correction, kept for the record

A forensic **trust-anchor** ("name the last-good key state before trusting
in-band signatures") is an *investigation* tool. It does not belong stapled to
*onboarding* — importing it there quietly frames a prospective volunteer as a
risk. The kind and correct reading of the same concern: volunteers who do the
work do their own signing (or we discuss it) — so a newcomer's work is
provably *theirs*, credit where earned, never blamed for keystrokes they
didn't type. Attribution in the volunteer's favor, not suspicion.
